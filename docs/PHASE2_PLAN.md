# Phase 2 実装計画：対戦エンジンとCPU戦（2026-10-16 承認済み。回答と変更点は docs/SPEC.md 決定事項ログ #25〜#48）

## 1. ファイル構成

```
src/engine/
├─ battle/                     … 対戦エンジン（純粋関数。CPU戦と Phase 3 のサーバーで共用）
│   ├─ types.ts                … 対戦の状態・アクション・ログの型
│   ├─ rng.ts                  … シード付き乱数（状態は GameState に入る）
│   ├─ setup.ts                … createGame()：デッキ検証、シャッフル、先攻後攻、1ターン目の開始
│   ├─ apply.ts                … applyAction(state, action) → 新しい状態（入口）
│   ├─ turn.ts                 … ターン開始・終了の処理、勝敗判定
│   ├─ play.ts                 … カードの使用、対象の確定、コスト（凍結・軽減）
│   ├─ queue.ts                … 効果の解決キューと「選択待ち」（サーチ・回収などで途中停止→再開）
│   ├─ combat.ts               … モンスターの攻撃（挑発・飛行・隠密・混乱・貫通・二回攻撃…）
│   ├─ damage.ts               … ダメージ計算（筋力・弱体・脆弱・守備力・出血・無効化・シールド）
│   ├─ status.ts               … 状態異常の付与・経過
│   ├─ triggers.ts             … タイミングごとの発動（攻撃するたび、ターン開始時、カードを使うたび…）
│   ├─ api.ts                  … 効果ファイルから呼ぶ道具（ダメージ、回復、ドロー、召喚、破壊…）
│   ├─ legal.ts                … legalActions()：今できる行動の一覧（UI・CPU・サーバーの検証で共用）
│   ├─ view.ts                 … viewFor()：相手の手札・山札の順番を隠した状態（Phase 3 の配信用）
│   └─ log.ts                  … ログ文言（効果の発動順とダメージの計算過程）
├─ ai/
│   ├─ cpu.ts                  … CPU の入口。戦略を差し替えられる形（Strategy インターフェース）
│   ├─ greedy.ts               … 「使える行動を評価値の高い順に使う」簡単な戦略
│   └─ evaluate.ts             … 盤面の評価関数
├─ defs/effects/*.ts           … 既存の各効果ファイルに「対戦での処理（resolve）」を追加
├─ defs/keywords/*.ts          … 各キーワードに対戦での働き（速攻・挑発…）を追加
└─ defs/drawbacks/*.ts         … 各デメリットに対戦での処理を追加
src/presets.ts                 … CPU用プリセットデッキ3つ（毒・モンスター・呪い）
src/ui/
├─ pages/BattleSetupPage.tsx   … デッキ選択（自分のデッキ／プリセット）、CPUのデッキ選択
├─ pages/BattlePage.tsx        … 対戦画面
└─ battle/                     … 盤面・プレイヤー情報・モンスター・手札・対象選択・選択ダイアログ・ログ
tests/battle/                  … ルールごとのテスト、全効果の処理テスト、CPU同士の自動対戦
```

効果を追加するときは、これまでどおり効果ファイル1つ（＋ balance.ts の数値）で、エディター・ポイント・テキスト・対戦処理のすべてに反映されます。

## 2. データ構造

```ts
type PlayerId = 0 | 1;
type TargetRef = { kind: 'player'; player: PlayerId } | { kind: 'monster'; uid: string };

interface GameState {
  v: 1;
  rng: number;                     // シード付き乱数の内部状態
  turn: number;                    // 経過ターン数（数え方は質問2）
  active: PlayerId;                // 手番のプレイヤー
  first: PlayerId;                 // 先攻
  players: [PlayerState, PlayerState];
  cards: Record<string, CardDef>;  // この対戦で使うカード定義（開始時に検証済み）
  queue: Step[];                   // 解決待ちの効果・トリガー
  pending: PendingChoice | null;   // プレイヤーの選択待ち（サーチ・回収・複製・解除・保持）
  result: { winner: PlayerId | null; reason: 'hp' | 'turnLimit' | 'concede' } | null;
  log: LogEntry[];
  nextUid: number;
}

interface PlayerState {
  name: string;
  hp: number; maxHp: number; shield: number; energy: number;
  deck: CardInst[]; hand: CardInst[]; discard: CardInst[]; exile: CardInst[];
  board: Monster[];                // 最大5体
  powers: PowerInst[];             // 場に残っているパワー（解除の対象）
  status: Statuses;                // 毒・やけど・弱体・脆弱・出血・凍結・反撃・無効化・再生・筋力・気合
  nextTurn: { draw: number; energy: number };  // 貯金・反動・ドロー妨害・エナジー妨害・施し
  thisTurn: { cardsPlayed: number; drawn: number; energyGained: number; discount: number; retain: number;
              cardPlayedTriggers: Record<string, number> };
}

interface CardInst { uid: string; cardId: string; owner: PlayerId; noise?: true; copy?: true }

interface Monster {
  uid: string; card: CardInst; owner: PlayerId; controller: PlayerId;
  attack: number; hp: number; maxHp: number; defense: number;
  summonedTurn: number; attacksUsed: number;
  sealed: boolean; undyingUsed: boolean; stealthUntilTurn: number | null;
  status: Statuses;
}

type Action =
  | { type: 'playCard'; player: PlayerId; cardUid: string; targets: { enemy?: TargetRef; ally?: string } }
  | { type: 'attack'; player: PlayerId; attackerUid: string; target: TargetRef }
  | { type: 'removeNoise'; player: PlayerId; cardUid: string }
  | { type: 'choose'; player: PlayerId; picks: string[] }
  | { type: 'endTurn'; player: PlayerId }
  | { type: 'concede'; player: PlayerId };

applyAction(state, action): { ok: true; state: GameState } | { ok: false; error: string };
legalActions(state, player): Action[];
viewFor(state, player): PlayerView;   // 相手の手札は枚数だけ、山札は枚数だけ
```

- 内部では状態を丸ごと複製してから書き換えるので、外から見ると「状態とアクションを受け取り、新しい状態を返す」純粋関数です。
- 乱数は状態の中に持つので、同じシード・同じ行動なら必ず同じ結果になります（テストとサーバー検証に使う）。
- 効果ファイルの処理関数は `resolve(battle, ctx)` の形で、api.ts の道具（`dealDamage`・`heal`・`addStatus`・`draw`・`summon`・`destroy` など）を呼ぶだけにして短く保ちます。
- ログは `{ turn, player, depth, text }`。depth で「カード使用 → 効果 → ダメージ計算」の入れ子を表し、画面では字下げして表示します。
  例：「火の粉を使った」→「相手に2ダメージ：基本2 → 脆弱+50%で3 → シールドが3を防いだ → HP 60」

## 3. CPU

- `Strategy` インターフェース（`chooseAction(view) → Action`）にして、後で強い戦略に差し替えられるようにします。
- 最初の戦略（貪欲法）：今できる行動を1つずつ仮に実行して盤面を評価し、評価値が一番高い行動を選ぶ。を「ターン終了」が一番よくなるまで繰り返します。
- CPU は `viewFor()` で見える情報だけを使います（相手の手札や山札の順番を覗かない）。仮の実行には本物とは別の乱数を使います。
- 評価関数：HP差、シールド、場のモンスターの強さ、状態異常、手札とエナジーの残りなど。重みは ai/ の中にまとめます（ゲームのバランス数値ではないため balance.ts とは分けます）。

## 4. プリセットデッキ

毒中心・モンスター中心・呪いカード中心の3つ。すべてカード作成ルールとデッキルールを満たすことをテストで保証します。カードの中身はこちらで作り、終わりに一覧をお見せします。

## 5. 対戦画面

- 対戦の準備：自分のデッキ（保存済みの合法なデッキ、またはプリセット）と、CPU のデッキを選んで開始。先攻後攻は質問29。
- 盤面（スマホは縦1列、PCは右にログ）
  - 相手：HP（バー）、シールド、状態異常、エナジー、山札・捨て札・手札の枚数、場のパワー、場のモンスター
  - 自分：同じ情報と手札（カード風）
  - ログ：細かめ。スマホでは折りたたみ
- 操作：手札をタップ → 対象が要るなら光った対象をタップ → 使用。自分のモンスターをタップ → 攻撃先をタップ。サーチ・回収などは選択ダイアログ。「ターン終了」ボタン。
- CPU の手番は1手ずつ間を置いて再生し、ログが流れるのを見られるようにします。
- 対戦中の状態は localStorage に残し、再読み込みしても続きから再開できるようにします。

## 7. 質問（仕様に書かれていない対戦ルール）

推奨案をそれぞれ書いています。「推奨で」でも、番号を指定しての変更でも大丈夫です。

### ターンの流れ
1. **エナジーの持ち越し**：推奨＝持ち越さない（毎ターン3に戻る）。貯金の効果があるため。
2. **「30ターン経過で引き分け」の数え方**：推奨＝両者のターンを1つずつ数えて合計30（各15ターン）。状態異常のターンも各プレイヤーのターンで数えるため。別案＝各プレイヤー30ターン。
3. **両者が同時にHP0**（全体ダメージ・自傷など）：推奨＝引き分け。
4. **ターン開始・終了の処理順**：推奨は次のとおり。
   - 開始：シールドと反撃が消える → 毒 → 再生 → 維持費 → 自己修復 → エナジーを得る → 5枚引く → 「自分のターン開始時」の効果（パワーを使った順 → 場のモンスターを左から）→ 裏切り
   - 終了：「自分のターン終了時」の効果 → 寄生 → やけど → 出血が半分 → 保持の選択 → 手札を捨てる → このターン限りの効果（気合など）が切れる
   - 途中でどちらかのHPが0になったら、その時点で試合終了。

### ダメージ
5. **筋力・気合が乗るダメージ**：推奨＝アタック・パワーアタックカードの使用時のダメージと連撃（1回ごとに加算）だけ。モンスターの攻撃、パワーやモンスターの効果のダメージには乗らない。
6. **ダメージの計算順**：推奨＝基本値（＋筋力・気合）→ 弱体−25%（切り捨て）→ 脆弱+50%（切り捨て）→ 守備力を引く → 最低1 → 出血を足す → 無効化 → シールドが肩代わり → HP。カードのダメージもモンスターの守備力で減る（連撃の説明に合わせる）。
7. **出血の「攻撃を受けるたび」**：推奨＝モンスターの攻撃と、ダメージ・連撃の1回ごと（毒・やけど・反撃・自傷は含まない）。出血の追加分は守備力で減らないが、シールドは肩代わりする。
8. **反撃**：推奨＝プレイヤーにかかる（モンスターカードの効果でも持ち主のプレイヤー）。期間中は攻撃（7と同じ範囲）を受けるたびに何度でも返す。返すダメージは普通のダメージ（相手がモンスターなら守備力で減る）。
9. **無効化**：推奨＝使われるまで残る。毒・やけど・自傷も含めて、次に受けるダメージ1回を0にする。重ねると回数が増える。
10. **吸収**：推奨＝実際に減らしたHP・体力の半分（シールドに防がれた分は数えない）を回復。
11. **貫通**：推奨＝余ったダメージは相手プレイヤーへの普通のダメージ（シールドで防げる）。

### 状態異常・キーワード
12. **やけどの重ねがけ**：推奨＝残りターン+1に加えて、新しいやけどの延長ターン分も足す。
13. **混乱したモンスターの攻撃先**：推奨＝相手側の攻撃できる対象（挑発・隠密のルールは守る）からランダム。味方は攻撃しない。
14. **封印**：推奨＝効果とキーワードは失うが、デメリット（維持費・裏切り）は残る。
15. **隠密**：推奨＝相手モンスターの攻撃と、相手のカードの「選んだ1体」で選べない。ランダムや全体の効果には当たる。
16. **不屈**：推奨＝ダメージで体力が0になるときだけ1で踏みとどまる。処刑・全体破壊などの「破壊」には効かない。
17. **裏切り**：推奨＝召喚したあと持ち主のターンを3回迎えたら、それ以降の持ち主のターン開始時に、自動で持ち主のプレイヤーを攻撃する（そのターンの攻撃回数を使う）。
18. **「ダメージを受けたとき」**：推奨＝ダメージを受けて生き残ったときだけ発動。破壊されたら「破壊されたとき」が発動する。

### カードと効果
19. **1枚に「選んだ1体」が複数あるとき**（例：火の粉のダメージとやけど）：推奨＝相手側・自分のモンスターそれぞれ1回だけ選び、同じ側の「選んだ1体」はすべてその対象にかかる。
20. **条件の「相手」**（相手が毒状態、相手のHP、毒とやけど）：推奨＝相手プレイヤーを見る。
21. **解除**：推奨＝相手の場にあるパワー1枚を使う側が選んで消す。そのパワーで得た筋力も消える。
22. **蘇生**：推奨＝捨て札から選んで場に出す。召喚と同じ扱い（召喚時の効果が発動し、次の自分のターンから攻撃できる）。場がいっぱいなら何も起きない。
23. **奪取**：推奨＝奪ったモンスターは次の自分のターンから攻撃できる。破壊・バウンスされたら元の持ち主の捨て札・手札へ行く。自分の場がいっぱいなら何も起きない。
24. **複製**：推奨＝コピーは使ったら除外される（その試合のデッキには残らない）。
25. **「カードを使うたび」の1ターン3回**：推奨＝パワー1枚ごとに3回まで。自分がカードを使い終えたあとに発動する。
26. **軽減の重ねがけ**：推奨＝重ねた分だけ次の1枚が安くなる（最低0）。
27. **1ターンに引ける10枚・エナジー+3**：推奨＝10枚はターン開始の5枚とドロー効果・施しを含む（サーチ・回収・複製は含まない）。+3 はエナジー効果と貯金の合計（反動・妨害による減少は別に引く）。
28. **ノイズを除外する操作**：推奨＝「カードを使った」ことには数えない（カードを使うたび・3枚目以降の条件・凍結のコスト+1・軽減に関係しない）。
29. **先攻・後攻**：推奨＝対戦開始時にランダム。
30. **決定事項ログ #9**（自分のモンスターを対象にする効果は、使用時・召喚時以外はランダムのみ）：推奨＝このまま。

## 8. 自分で決める実装判断（承認後に決定事項ログへ記録）

- 手札の上限は設けない（1ターンに引ける10枚で実質的に制限される）。マリガン（引き直し）はなし。
- 場が5体のときはモンスターカードを使えない。
- 対象がいない効果（例：相手モンスターがいないときの処刑）を持つカードも使える。その効果は何も起きない。条件を満たさない効果も同じ。
- 同時に発動するものは、手番のプレイヤー側から、パワーを使った順 → 場のモンスターを左から、の順に処理する。
- パワーの「ターン開始時／終了時」は、使った次のタイミングから発動する。
- サーチ・回収で選んだあとは山札をシャッフルする。
- コストが足りないカードは使えない（凍結のコスト+1も含む）。
- 試合の状態はすべて JSON にできる形にする（サーバー保存・再開・テストのため）。
