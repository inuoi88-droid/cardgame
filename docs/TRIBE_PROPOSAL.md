# 種族の特徴：土台の案（決定事項 #143 で実装）

種族（獣・竜・不死・機械・精霊・人）に数値上の意味を持たせる案。3つの方向を組み合わせる。

1. 得意・苦手
2. 常時の特性
3. 揃えたときのボーナス

見た目（背景の場面と種族の印）は決定事項 #142 で入れ済み。ここに書いた数字はすべて**最初の値**。実装したらシミュレーションで測り直して決める（CLAUDE.md の手順）。

> **決まったこと（ユーザー回答）**：得意 0.8 倍・苦手 1.25 倍／特性は無料で小さく／揃いは**すべて3体**（竜も3体）／3つまとめて入れて測る。精霊の「共鳴」は、手札をターン終了時に捨てる決まりがあるので「ターン終了時に1枚引く」ではなく「ターン開始時に1枚多く引く」にした。今の値と測定の結果は docs/SPEC.md の決定事項 #143。
>
> **測定のあとの見直し（ユーザー回答）**：完全に無効にする特性はやめる。竜鱗＝自分のターン終了時にやけどの残りがさらに1減る／鋼の体＝自分のターン終了時に毒が20減る（倍率1で1）／霊体＝出てから次の自分のターンまで、相手のカードの効果で受けるダメージが半分（選ばれはする）／連結＝守備力+10（倍率1で0.5）／竜の息・隊列＝60（倍率1で3）。下の表は最初の案のまま残す。

## 1. 得意・苦手（ポイントの割引と割増）

種族ごとに「得意」と「苦手」のキーワード・効果を決める。

- **得意**：ポイントが `favorRate`＝**0.8 倍**（2割引き）。
- **苦手**：ポイントが `unfavorRate`＝**1.25 倍**（2割5分増し）。

| 種族 | 得意（安い） | 苦手（高い） | ねらい |
|---|---|---|---|
| 獣 | 速攻・貫通・猛襲・二回攻撃 | 呪禁・護法 | 速く殴る |
| 竜 | 飛行・威圧・呪禁 | 隠密・潜伏 | 大きく目立つ空の王 |
| 不死 | 不屈・接死・絆魂・効果「蘇生」 | 聖盾・自己修復・効果「回復」 | しぶとく、命を奪う |
| 機械 | 守備力（ステータス）・自己修復・聖盾・対空・効果「修理」 | 速攻・隠密 | 硬く、直して粘る |
| 精霊 | 隠密・護法・潜伏・効果「占術」 | 挑発・貫通 | 捕まらない |
| 人 | 挑発・武士道・効果「装備」・効果「回復」 | なし（器用） | 守りと鍛え上げ |

- **モンスターのカードだけ**に効く。呪文の種族はこれまでどおり「同じ種族」系の目印だけにする。呪文に種族を付けるだけで「ドロー」などが安くなる抜け道をふさぐため。
- エディターのポイントの内訳に「種族（獣）の得意：−N」「種族（竜）の苦手：+N」の行を足す。選択パネルの選択肢には「得意」「苦手」の札を付ける。
- 置き場所は balance.ts の `tribes`（下の 4 を参照）。points.ts の `calculatePoints` に割引の行を1つ足す（`modeDiscount` と同じ形）。

**公式カードへの影響**（実際の倍率で計算）：

- 種族のあるモンスター67枚の平均で、ポイントがレアリティの上限の約7%（人は約11%）下がる（得意を持たないカードは変わらない。いちばん下がるのは城塞の大盾兵の32%）。
- 予算の3割より多く余るカードが **13枚**出る（群れ狼・城門の衛兵・城塞の大盾兵・双頭の魔狼など）。
- 苦手で上限を超えるカードは0枚。
- 余った分は数値を足して埋め直す。つまり、種族のある公式モンスターが少し強くなる。

## 2. 常時の特性（その種族のモンスターがみな持つ）

小さく、種族ごとに違う形の特性にする。**ポイントは0（無料）**を提案する。

一律に x(0.5) を払わせる案も試算した。この案だと、予算を使い切っているコモン4枚（城壁の弓兵・偵察のからくり鳥・からくりの助手・森の大精霊）が上限を超えて作れなくなる。さらに、値段に見合うかどうかがカードによって大きく変わる（体力1のモンスターの耐性と大型の耐性では価値が違う）。

| 種族 | 名前 | 中身 | 数値（倍率1） |
|---|---|---|---|
| 獣 | 狩猟本能 | 攻撃で相手のモンスターを破壊するたび、攻撃力+1（場にいる間。最大+3） | `attackPerKill: x(1)`・`maxBonus: x(3)` |
| 竜 | 竜鱗 | やけど・凍結にならない | `immune: ['burn', 'freeze']` |
| 不死 | 腐食 | 攻撃・反撃でダメージを与えた相手のモンスターに毒1 | `poisonOnHit: x(1)` |
| 機械 | 鋼の体 | 毒・出血にならない | `immune: ['poison', 'bleed']` |
| 精霊 | 霊体 | 場に出てから次の自分のターンが始まるまで、相手のカードに選ばれない | `untargetableTurns: 1` |
| 人 | 研鑽 | 攻撃力アップ・鍛錬・装備で上がる攻撃力が、さらに+1 | `growBonus: x(1)` |

- 封印中のモンスターでは特性が働かない（キーワードと同じ扱い）。裏向きのモンスターは種族が無いものとして扱う。
- 対戦の仕組み側では、1か所の `tribeHooks(g, m)` から読む（`ruleHooks` と同じ形）。状態異常を付ける共通の処理・combat.ts の戦闘ダメージ・対象の選び方（damage.ts の `targetableTaunts` の近く）に差し込む。
- 画面：カードの詳細と種族の印のポップオーバーに特性の文を出す。ルールのページに種族の節を足す。

## 3. 揃えたときのボーナス（場に同じ種族が並んでいる間）

自分の場に同じ種族のモンスターが **3体以上** いる間、ずっと効く（案では竜だけ2体だったが、すべて3体に決まった）。

| 種族 | 名前 | 中身 | 数値（倍率1） |
|---|---|---|---|
| 獣 | 群れ | 自分の獣の攻撃力+1 | `set.attack: x(1)` |
| 竜 | 竜の息 | 自分のターン開始時、相手プレイヤーに2ダメージ | `set.breath: x(2)` |
| 不死 | 怨嗟 | 自分の不死が破壊されるたび、相手プレイヤーに2ダメージ | `set.onDeath: x(2)` |
| 機械 | 連結 | 自分の機械の守備力+1 | `set.defense: x(1)` |
| 精霊 | 共鳴 | 自分のターン開始時、カードを1枚多く引く | `set.draw: 1` |
| 人 | 隊列 | 自分のターン開始時、自分のプレイヤーが2回復 | `set.healAtStart: x(2)` |

- 数えるのは、表向きで場にいる、その種族のモンスター（トークン・複写も種族があれば数える）。
- 攻撃力・守備力は core.ts の `effectiveAttack` と守備力の読み出しで足す（激励と同じく、場の様子で毎回決まる）。そのため、揃いが崩れれば自然に元に戻る。
- 竜の息・隊列はターン開始時のフック、共鳴はターン終了時のフック、怨嗟は破壊の共通処理（`onLeaveBoard` の近く）に入れる。
- ログには ev を付ける（演出・音は `EFFECT_FX` 相当の台帳に足す）。
- 画面：プレイヤーの銘板の近くに「獣×3 群れ」の札を出す（揃っている間だけ。あと1体なら薄く出す案もある）。
- カードのポイントには入れない（場で生まれる強さなので、測って数値で合わせる）。

## 4. balance.ts の形（案）

```ts
tribes: {
  /** 得意：ポイントの倍率（モンスターのカードだけ） */
  favorRate: 0.8,
  /** 苦手：ポイントの倍率 */
  unfavorRate: 1.25,
  /** 揃えたときのボーナスに要る数（種族ごとの setSize が優先） */
  setSize: 3,
  beast: {
    favored: ['haste', 'trample', 'onslaught', 'doubleAttack'],
    unfavored: ['hexproof', 'ward'],
    trait: { attackPerKill: x(1), maxBonus: x(3) },
    set: { attack: x(1) },
  },
  dragon: {
    favored: ['flying', 'menace', 'hexproof'],
    unfavored: ['stealth', 'skulk'],
    trait: { immune: ['burn', 'freeze'] },
    set: { size: 2, breath: x(2) },
  },
  undead: {
    favored: ['undying', 'deathtouch', 'lifelink', 'revive'],
    unfavored: ['divineShield', 'selfRepair', 'heal'],
    trait: { poisonOnHit: x(1) },
    set: { onDeath: x(2) },
  },
  machine: {
    favored: ['stat:defense', 'selfRepair', 'divineShield', 'reach', 'repair'],
    unfavored: ['haste', 'stealth'],
    trait: { immune: ['poison', 'bleed'] },
    set: { defense: x(1) },
  },
  spirit: {
    favored: ['stealth', 'ward', 'skulk', 'scry'],
    unfavored: ['taunt', 'trample'],
    trait: { untargetableTurns: 1 },
    set: { drawAtEnd: 1 },
  },
  human: {
    favored: ['taunt', 'bushido', 'equip', 'heal'],
    unfavored: [],
    trait: { growBonus: x(1) },
    set: { healAtStart: x(2) },
  },
},
```

ID の一覧はキーワード・効果・ステータスを区別せずに並べる（ステータスは `stat:` を付ける）。テストで「どの ID も登録にある」ことを確かめる。

## 5. 進め方と測り方

3つを一度に入れると、どれが効いたのか分からなくなる。順に入れて、そのつど測る。

1. **得意・苦手**（ポイントだけ。いちばん安全）
   - 公式カード13枚を埋め直す。
   - `tests/*.test.ts` と `*.real.test.ts`、`tests/official*.test.ts` の予算の3割を通す。
2. **特性**（エンジン・CPU・画面）
   - 種族ごとに、特性あり／なしで同じデッキを戦わせ、勝率の差を見る。
3. **揃いのボーナス**（エンジン・CPU の評価・画面）
   - 極端なデッキを作って測る（`scripts/sim/stress.mts` に「全部獣」「全部機械」「全部人」など。竜は2体で揃うので「竜6枚」も）。
   - ドラフト戦では、同じ種族ばかり取る CPU の取り方（pick.ts に種族の重み）と、おまかせの取り方を戦わせる（`node scripts/sim/official.mts draft|pickers`）。

**目安**（これまでの測定と同じ考え方）：

- 揃いのボーナスで、片寄ったデッキがふつうのデッキに勝つ割合が **55% 前後**。60% を超えたら下げる。
- 試合の長さは今と比べて ±1 ターン以内。
- 1ターン目〜3ターン目に決着する試合は増やさない（報告 #4・#5 の OTK の測定と同じ）。

CPU：

- evaluate.ts で、揃いまで「あと1体」の価値を見るようにする。
- lethal.ts で、竜の息・怨嗟のダメージを数えるようにする。
- ドラフトの pick.ts で、同じ種族を取る重みを足す。

## 6. 決めてほしいこと

1. 得意・苦手の倍率（案：得意 0.8／苦手 1.25。人は苦手なし）
2. 特性のポイント（案：無料で小さく）
3. 揃いの数（案：3体、竜は2体）と、ボーナスの中身
4. 各種族の得意・苦手・特性の中身（上の表で直したいところ）
5. 精霊のカードが公式に1枚しかないこと（あとで公式カードの種族を見直す。たとえば毒の種族なしのモンスターを精霊か獣にする）
